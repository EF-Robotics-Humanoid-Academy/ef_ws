Task 11 — Dex3 Gradual Gripping (baseline, close, and open)

A Dex3 HandCmd message carries one motor command per hand joint; every commanded joint needs control mode, target position, and conservative dq/tau/kp/kd. This task measures an unloaded tactile noise baseline, then implements both directions of gradual motion — gradual_close (stopping early on tactile contact) and gradual_open (a graceful, symmetric release).

⚠ Verify HAND_OPEN/HAND_CLOSED on your hand before trusting them

The notebook's imports pull HAND_OPEN/HAND_CLOSED from util.py. Those tables do not agree with the ones sdk_wrapper.py actually uses at runtime (in G1.open_dex3_hand/close_dex3_hand/HAND_MIN/HAND_MAX):

  • Right hand, joints thumb_1/thumb_2 (indices 1–2): util.py's OPEN/CLOSED values for these two joints are swapped relative to sdk_wrapper.py's computed HAND_OPEN/HAND_CLOSED.
  • Left hand, joints middle_0/middle_1/index_0/index_1 (indices 3–6): same swap.

Concretely: util.HAND_CLOSED["right"] = [-0.0351, 0.742, 0.0, 1.57, 1.75, 1.57, 1.75], but sdk_wrapper.HAND_CLOSED["right"] (derived from its own HAND_MIN/HAND_MAX tables) is [-0.0351, -1.05, -1.75, 1.57, 1.75, 1.57, 1.75] — index 1/2 disagree.

Before you write hand-closing code against a real hand: run gradual_close at a very slow rate first and visually confirm the fingers actually curl toward closed, not open. If you see the opposite of what you expect, use sdk_wrapper.py's HAND_MIN/HAND_MAX/HAND_OPEN/HAND_CLOSED tables instead of util.py's for the affected joints — they match what sdk_wrapper.G1's own hand methods send to the real robot. Flag this discrepancy to your instructor rather than silently picking one table.

§1Knowledge — the Dex3 HandCmd message and joint range

7 joints per hand: thumb_0, thumb_1, thumb_2, middle_0, middle_1, index_0, index_1 (3-DOF thumb + two 2-DOF fingers). Every commanded joint needs mode/q/dq/tau/kp/kd, same shape as Task 9's rt/lowcmd, just a different topic and a packed mode bit-field.

JointLeft range (rad)Right range (rad)
thumb_0 (fixed rotation)-0.099 (neutral)-0.035 (neutral)
thumb_1 / thumb_2-0.724..1.05 / 0..1.75-1.05..0.742 / -1.75..0
middle_0 / middle_1-1.57..0 / -1.75..00..1.57 / 0..1.75
index_0 / index_1-1.57..0 / -1.75..00..1.57 / 0..1.75

cmd.mode = (motor_index & 0x0F) | (1 << 4) — low nibble selects the joint, bit 4 enables it. Default gains kp=0.8, kd=0.05, tau=0.02 (much softer than the body's kp=40-100 — fingers need to comply, not fight contact).

§2Knowledge — calibrate the threshold, don't copy one

academy/todo.txt is explicit: grasp-contact thresholds are empirical per installation and per object class, never a constant copied from another robot or a different Dex3 unit.

gradual_close interpolates in small steps and checks tactile pressure after every step — it stops the moment any sensor crosses threshold, not at the end of the ramp. gradual_open is deliberately not symmetric in behavior: no tactile early-stop, because opening should always be gentle rather than snapping — snapping open can drop a held object suddenly or shock the fingers against their end stops.

Flow: measure_baseline() (no object, 2s) → note max/mean noise floor → supervised safe grasp, pick threshold above baseline → gradual_close(threshold) stops on contact.

§3Knowledge — assembly, services, and Inspire hands (context)

On-robot, the hand connects over the same internal bus the wrist publishes rt/dex3/<side>/cmd/state through — no separate IP or adapter needed once mounted. Off-robot (bench testing), Unitree's USB debug adapter lets a laptop talk to one hand directly.

Dex3 hands register their own named services with RobotStateClient (dex3_service_l/dex3_service_r) — outside Task 4/5's SERVICE_CATALOG, but visible via get_services() and toggleable via toggle_service(name), useful to confirm a hand's service is actually enabled before debugging a silent HandState_ subscriber.

Some G1 units ship Inspire 5-finger hands instead of Dex3 — controlled completely differently: raw Modbus TCP register writes (enable register 1004, preload registers 1522/1498, then 6 target registers at 1486), own IP per hand (right 192.168.123.210:6000, left 192.168.123.211:6000), no DDS, no tactile read-back in this repo.

class Latest:
    def __init__(self, topic, message_type, queue_len=10):
        self.message = None; self.timestamp = 0.0
        self.subscriber = ChannelSubscriber(topic, message_type)
        self.subscriber.Init(self._callback, queue_len)
    def _callback(self, message):
        self.message = message; self.timestamp = time.time()

hand_pubs = {"right": ChannelPublisher("rt/dex3/right/cmd", HandCmd_)}
hand_pubs["right"].Init()
hand_state_subs = {"right": Latest("rt/dex3/right/state", HandState_, 20)}
_last_hand_targets = {}

def write_hand(targets, side="right", kp=0.8, kd=0.05, tau=0.02):
    msg = unitree_hg_msg_dds__HandCmd_()
    for i, q in enumerate(targets):
        cmd = msg.motor_cmd[i]
        cmd.mode = (i & 0x0F) | (1 << 4)
        cmd.q = float(q); cmd.dq = 0.0; cmd.tau = tau; cmd.kp = kp; cmd.kd = kd
    hand_pubs[side].Write(msg)
    _last_hand_targets[side] = list(targets)              # gradual_open/close need their true starting pose

def tactile_samples(side="right"):
    msg = hand_state_subs[side].message
    if msg is None:
        return []
    return [float(v) for sensor in msg.press_sensor_state for v in sensor.pressure]

def measure_baseline(side="right", duration_s=2.0):
    samples = []
    deadline = time.time() + duration_s
    while time.time() < deadline:
        samples.extend(tactile_samples(side))
        time.sleep(0.02)
    if not samples:
        raise RuntimeError("No tactile samples received; check the HandState_ subscriber.")
    return {"max": max(samples), "mean": sum(samples) / len(samples), "n": len(samples)}

def gradual_close(threshold, side="right", steps=40, delay_s=0.05):
    start = _last_hand_targets.get(side, HAND_OPEN[side])
    for step in range(1, steps + 1):
        a = step / steps
        frame = [x + (y-x)*a for x, y in zip(start, HAND_CLOSED[side])]
        write_hand(frame, side=side)
        time.sleep(delay_s)
        samples = tactile_samples(side)
        if samples and max(samples) >= threshold:               # stop the moment contact is felt
            return {"contact": True, "step": step, "side": side}
    return {"contact": False, "step": steps, "side": side}       # closed fully, never touched anything

Hint: always run measure_baseline() fresh for the actual hand/installation you're testing on — never reuse a threshold value from a previous session or a different Dex3 unit.

Symmetric interpolation shape to gradual_close, but from the last-written targets (default HAND_CLOSED[side]) back to HAND_OPEN[side], with no tactile early-stop — opening should just complete gently, not snap open on any condition.

def gradual_open(side="right", steps=40, delay_s=0.05):
    start = _last_hand_targets.get(side, HAND_CLOSED[side])
    for step in range(1, steps + 1):
        a = step / steps
        frame = [x + (y-x)*a for x, y in zip(start, HAND_OPEN[side])]
        write_hand(frame, side=side)
        time.sleep(delay_s)
    return {"step": steps, "side": side}

Safety

Never hardcode a contact threshold — it must come from measure_baseline() plus a supervised safe-grasp calibration. Run no command cell until the subscriber state is fresh, controller ownership is known, the space is clear, and a damp path is available.
