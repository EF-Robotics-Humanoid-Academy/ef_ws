§1Knowledge — the mapping lifecycle

CallDoes
g1.start_mapping(slam_type="indoor")starts building a map from the LiDAR
g1.stop_mapping()saves the map (the end_mapping RPC) to the path hardcoded in sdk_wrapper (/home/unitree/test.pcd), so you can relocalize/navigate on it later — no path argument needed
g1.stop_mapping(save=False)closes SLAM (the close_slam RPC) without saving — only when you want to abort a mapping session
g1.relocate()loads that saved map and relocalizes — do this once after mapping, before navigating
g1.get_slam_pose()the last known (x, y, yaw) on the current map, or None

Build the map by driving the robot around the space with the hand-held remote controller (not loco_move) so the LiDAR sees the whole room, then save it with stop_mapping().

§2Knowledge — named points and navigation

g1.add_map_pose() appends the current SLAM pose to the wrapper's own path queue (consumed by g1.navigate()), but does not name it. To come back to a spot by name later, save it yourself — a tiny JSON dict of {name: [x, y, yaw]} on disk, keyed off g1.get_slam_pose(). That is exactly what g1.navigate_to_point(point_name, points_path="slam_points.json") expects to read.

CallDoes
g1.navigate_to_point(name, points_path=..., timeout_s=120.0)reads the named pose, sends it, blocks until arrival or timeout
g1.pause_nav() / g1.resume_nav()interrupt / continue an in-progress navigation
g1.loco_stop()immediate full stop, including mid-navigation

import json
from pathlib import Path

def add_point(g1, name, points_path="slam_points.json"):
    path = Path(points_path)
    points = json.loads(path.read_text()) if path.exists() else {}
    points[name] = list(g1.get_slam_pose())
    path.write_text(json.dumps(points))
    return points[name]

def remove_point(name, points_path="slam_points.json"):
    path = Path(points_path)
    points = json.loads(path.read_text()) if path.exists() else {}
    points.pop(name, None)
    path.write_text(json.dumps(points))

g1.relocate()
add_point(g1, "pickup")

§7Seeing the map

Two ways to actually look at what SLAM is doing, neither of which you need to build from scratch:

  • academy/visualizations/slam_web_app.py — a small web app that shows the live map and robot pose in a browser while mapping/navigating. Run it directly, or paste it into Codex and ask for a trimmed-down version if you want to change what it shows.
  • academy/visualizations/zmp_viz.py — a different concept: not the SLAM map, but a live Zero Moment Point (ZMP) plot — whether the robot's support point stays inside its support polygon while it walks. Run it alongside a loco_move() to see the balance margin in real time; you are not expected to build ZMP estimation yourselves.

Safety

Run no command cell until the subscriber state is fresh, controller ownership is known, the space is clear, and a damp path is available. Code is not invoked automatically.
